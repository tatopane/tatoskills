# Working with Antigravity Sidecars

This skill provides configuration guidelines, schema definitions, and best practices for creating, packaging, and managing sidecars in Antigravity.

## When to Use This Skill
Use this skill when:
- The user wants to run persistent background processes or scripts alongside Antigravity.
- You need to set up recurring cron-like actions (e.g., polling, summary reports, periodic testing).
- You are writing background workers or configuring notifications via `agentapi`.

---

## What is a Sidecar?
Sidecars are background processes managed by Antigravity. The platform launches them automatically at startup, monitors their state, and restarts them if they crash. They are ideal for persistent scripts, scheduled tasks, and event-driven actions.

---

## Configuration & Locations

Sidecars are discovered by the presence of a `sidecar.json` file inside their directory.

### Discovery Directories
- **Global Scope**: `~/.gemini/config/sidecars/<sidecarName>/`
  - The sidecar ID is `<sidecarName>`.
- **Plugin Scope**: `~/.gemini/config/plugins/<pluginName>/sidecars/<sidecarName>/`
  - The sidecar ID is `<pluginName>/<sidecarName>`.

*Note: The directory containing `sidecar.json` acts as the current working directory (Cwd) for the sidecar process.*

---

## Schema Definitions

### 1. The Sidecar Config (`sidecar.json`)
The directory must contain `sidecar.json`. One of `command` or `builtin` is required.

| Field | Type | Description |
| --- | --- | --- |
| `command` | string | Command/executable to run (e.g., `python3`, `/bin/bash`). Mutually exclusive with `builtin`. |
| `builtin` | string | Builtin command to execute. Currently supports `schedule`. Mutually exclusive with `command`. |
| `args` | array of strings | Optional. Arguments passed to the command or builtin. |
| `restart_policy` | string | Optional. Restart behavior: `"always"`, `"on-failure"`, or `"never"`. Defaults to `"always"`. |
| `description` | string | Optional. Human-readable description of what the sidecar does. |
| `env` | object | Optional. Environment variables map for the process. |
| `display_name` | string | Optional. UI display name. |

*Example (External command)*:
```json
{
  "description": "Background worker",
  "command": "python3",
  "args": ["worker.py"],
  "restart_policy": "on-failure"
}
```

*Example (Scheduled task)*:
```json
{
  "description": "Hourly reviewer agent",
  "builtin": "schedule",
  "args": [
    "0 * * * *",
    "agentapi",
    "new-conversation",
    "Give me a summary of incoming review requests."
  ]
}
```

### 2. User Activation (`config.json`)
Sidecars are **disabled by default**. Users must explicitly enable them in `~/.gemini/config/config.json`:

```json
{
  "sidecars": {
    "sidecar1": {
      "enabled": true
    },
    "my-plugin/plugin-sidecar": {
      "enabled": true,
      "projectId": "my-gcp-project-123"
    }
  }
}
```
- **`enabled`** (boolean): Enforces whether the background process runs.
- **`projectId`** (string, optional): Required if the sidecar creates new conversations using the `agentapi` CLI tool.

## Runtime Environment & Data

Runtime files generated by sidecars are stored in `~/.gemini/antigravity/sidecar_data/<sidecarId>/`:
- **`data/`**: Directory for persistent state. The path is injected into the sidecar process as the `ANTIGRAVITY_EXECUTABLE_DATA_DIR` environment variable.
- **`logs/`**: Timestamped logs capturing stdout and stderr.
- **`events/`**: Recorded JSON logs for `agentapi` requests.

---

## Builtin Actions & Utilities

### 1. The `schedule` Builtin
The builtin `schedule` command operates as a cron executor. The first argument is a 5-field cron expression, and the remaining arguments specify the action:
```json
{
  "builtin": "schedule",
  "args": [
    "*/5 * * * *",
    "python3",
    "check_status.py"
  ]
}
```

### 2. Programmatic Interaction via `agentapi`
Sidecars have access to the `agentapi` CLI automatically in their `$PATH`. This lets them trigger conversations:
- **Create Conversation**:
  `agentapi new-conversation <prompt>` (Requires `projectId` in user's `config.json`).
- **Send Message**:
  `agentapi send-message <conversation_id> <prompt>`

## Best Practices

### 1. Prefer `schedule` over Infinite Sleep Loops
To run recurring tasks, configure the `schedule` builtin with a cron expression. Avoid writing scripts with `while True: sleep(3600)` because it makes it harder for the host system to manage CPU resources and detect crashes.

### 2. Use `ANTIGRAVITY_EXECUTABLE_DATA_DIR` for State
Never hardcode configuration file paths inside your scripts. Write all state, caches, and configuration to the directory specified by the `ANTIGRAVITY_EXECUTABLE_DATA_DIR` environment variable.

### 3. Graceful Crash Handling
Ensure you choose the correct `restart_policy`:
- Use `on-failure` or `always` for long-running processes (like websocket listeners).
- Use `never` for sidecars meant to run once per workspace startup.
- Log error context to stderr so it is archived in the sidecar's `logs/` directory for easy troubleshooting.
